# CLAUDE.md - MOCHU-OA V2.0 AI 辅助开发指南

## 欢迎

你是 MOCHU-OA V2.0 施工管理系统的 AI 开发助手。本文档定义了你的工作流程和开发规范。请严格遵守这些规则。

---

## 工作流程（必须按顺序执行）

### 步骤 1: 读取任务列表
首先，读取 `task.json` 文件，找到一个状态为 `pending` 的任务。

**选择任务的优先级规则：**
1. 优先选择 `priority: "high"` 的任务
2. 检查任务的 `dependencies`，确保依赖的任务都已完成
3. 如果有多个符合条件的任务，选择 `id` 最小的那个

### 步骤 2: 标记任务开始
在 `task.json` 中找到该任务，更新：
```json
{
  "status": "in_progress",
  "assignee": "AI-Agent",
  "started_at": "2026-04-06T18:45:00+08:00"
}
```

同时在 `progress.txt` 中添加记录：
```
### 2026-04-06 18:45:00 - 开始任务 TASK-XXX
- **任务**: 任务标题
- **操作**: 标记任务为进行中
- **状态**: 开始执行
```

### 步骤 3: 执行开发任务
根据任务描述进行开发。开发过程中请遵循以下规范：

#### 3.1 代码规范
- **Java 代码**：遵循 Google Java Style Guide
- **Vue 代码**：遵循 Vue 3 Composition API 最佳实践
- **命名规范**：
  - 类名：PascalCase（如 `UserService`）
  - 方法名：camelCase（如 `getUserById`）
  - 常量：UPPER_SNAKE_CASE（如 `MAX_RETRY_COUNT`）
  - 数据库表名：snake_case（如 `biz_contract`）

#### 3.2 注释规范
- 所有类必须添加类注释（说明用途、作者、创建时间）
- 所有 public 方法必须添加方法注释（说明参数、返回值、异常）
- 复杂逻辑必须添加行内注释

#### 3.3 测试要求
- 每个功能模块必须编写单元测试
- 测试覆盖率目标：≥80%
- 测试命名：`test{方法名}_{场景描述}`

### 步骤 4: 测试与验证
开发完成后，必须：
1. 编写单元测试
2. 运行测试确保通过
3. 进行代码自审

如果测试失败，修复代码直到所有测试通过。

### 步骤 5: 更新进度文件
在 `progress.txt` 中详细记录：
```
### 2026-04-06 19:30:00 - 完成任务 TASK-XXX
- **任务**: 任务标题
- **操作**: 详细描述完成了什么工作
- **状态**: 成功/失败
- **详情**:
  - 创建了 XXX 文件
  - 实现了 XXX 功能
  - 编写了 XXX 测试
  - 测试结果：通过/失败
```

### 步骤 6: 更新任务状态
在 `task.json` 中更新任务状态：
```json
{
  "status": "completed",
  "completed_at": "2026-04-06T19:30:00+08:00"
}
```

### 步骤 7: Git 提交代码
使用 Git 提交你的更改。提交信息格式：

```
[TASK-XXX] 简短描述

详细描述本次提交的内容：
- 实现了 XXX 功能
- 修复了 XXX 问题
- 添加了 XXX 测试

Related: #issue_number (如有)
```

**Git 提交命令：**
```bash
git add .
git commit -m "[TASK-XXX] 简短描述"
git push origin main
```

## 遇到困难时的处理

### 如果你遇到以下情况，必须向人类求助：
1. **需求不明确**：任务描述不清楚，无法确定具体实现方式
2. **技术选型困难**：存在多种实现方案，无法确定最佳方案
3. **依赖阻塞**：依赖的任务未完成，或依赖的服务不可用
4. **权限问题**：需要访问特定的资源或服务，但权限不足
5. **设计冲突**：发现需求规格说明书中存在矛盾或不合理的地方

### 求助方式：
在 `progress.txt` 中添加求助记录：
```
### 2026-04-06 18:50:00 - 需要人类协助
- **任务**: TASK-XXX
- **问题类型**: 需求不明确/技术选型/依赖阻塞/权限问题/设计冲突
- **详细描述**: 清楚地描述遇到的问题
- **建议方案**: 如果有建议方案，可以列出
- **等待**: 等待人类反馈
```

**重要：** 在得到人类反馈之前，不要继续执行该任务。你可以：
- 选择其他不依赖此问题的任务继续工作
- 或者停止工作，等待反馈

1. **不要猜测**：如果不确定某个实现细节，查阅需求规格说明书或向人类求助
